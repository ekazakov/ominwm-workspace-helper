# Техническое задание: OmniWM Workspace Column Mover для Hammerspoon

## 1. Цель

Разработать расширение для Hammerspoon, позволяющее с помощью клавиатуры переносить **сфокусированную колонку OmniWM** в выбранный workspace.

Расширение должно показывать компактное меню, содержащее список воркспейсов с названиями и иконками уже открытых в них приложений, аналогично Workspace Bar OmniWM.

Приоритеты разработки:

1. Минимальная задержка открытия меню.
2. Надёжный перенос всей колонки, а не отдельного окна.
3. Отображение актуальных воркспейсов и приложений.
4. Минимальное потребление памяти и CPU.
5. Простая установка и отсутствие сторонних зависимостей.

## 2. Технологии и ограничения

- macOS.
- OmniWM 0.7.6, режим Niri.
- Hammerspoon с Lua.
- `hs.chooser` — интерфейс выбора.
- `hs.canvas` — создание составных изображений.
- `hs.image` — получение иконок приложений.
- `hs.task` — асинхронное выполнение CLI-команд.
- `hs.json` — обработка JSON.

Не использовать `hs.webview`, JavaScript, Python, `jq`, Homebrew-библиотеки или дополнительные процессы, работающие постоянно без необходимости.

Реализовать решение преимущественно средствами встроенного API Hammerspoon.

## 3. Пользовательский сценарий

1. Пользователь фокусирует окно в колонке OmniWM.
2. Нажимает настраиваемый глобальный шорткат.
3. Открывается меню выбора workspace.
4. Меню показывает все доступные воркспейсы, их названия и иконки приложений.
5. Пользователь выбирает destination с помощью стрелок или поиска.
6. Нажимает `Enter`.
7. Меню закрывается, а вся исходная колонка перемещается в выбранный workspace.

При нажатии `Escape` меню закрывается без изменений.

### Управление

| Клавиша | Действие |
|---|---|
| Настраиваемый Hyper + W | Открыть/закрыть меню |
| `↑` / `↓` | Выбрать workspace |
| `Enter` | Переместить колонку |
| `Escape` | Отменить |
| Ввод текста | Фильтрация воркспейсов |

Поиск должен работать по номеру, названию workspace и желательно по названиям приложений.

Использовать штатные возможности поиска `hs.chooser`.

Шорткат определяется в конфигурации, без жёсткой привязки в логике расширения.

## 4. Интерфейс

Использовать один экземпляр `hs.chooser`, создаваемый при инициализации Hammerspoon.

Каждый элемент списка содержит:

- Составную иконку из значков приложений.
- Номер или идентификатор workspace.
- Отображаемое имя workspace.
- Дополнительную информацию об открытых приложениях.
- Визуальное обозначение текущего workspace.

Пример концептуального содержимого:

    [VSCode][Terminal][Docker]  1 — Development
    [Safari][Chrome]            2 — Browser
    [Telegram][Slack]           3 — Communication
    [No apps]                   4 — Empty

Это пример структуры данных, а не требование к точному расположению элементов.

Учитывать ограничения `hs.chooser`: его стандартное поле `image` располагается рядом с текстом, а не в произвольном месте строки.

Требования к отображению:

- Тёмное оформление, близкое к Command Palette OmniWM.
- Компактные строки.
- Чёткие иконки.
- Удобная читаемость названий.
- Отображение пустых workspace.
- Корректная работа с длинными названиями.
- Поддержка Unicode и emoji.
- Поддержка workspace с номерами больше 9.

Точное визуальное совпадение с OmniWM не требуется.

### Иконки приложений

Получать иконки локально через `hs.image.imageFromAppBundle(bundleId)`.

Для каждого workspace формировать одно составное изображение через `hs.canvas`.

Требования:

- Размер каждой иконки — примерно 20–24 pt.
- Максимум 4–5 иконок в составном изображении.
- Если приложений больше, показывать `+N`.
- При нескольких окнах одного приложения отображать одну иконку, группируя по `bundleId`.
- Если `bundleId` неизвестен или иконка недоступна, использовать нейтральную иконку.
- Не загружать иконки из интернета.
- Не создавать и не уничтожать canvas при каждом открытии меню без необходимости.

Количество видимых иконок сделать настраиваемым.

## 5. Интеграция с OmniWM

Использовать `omniwmctl`.

Основные команды:

```bash
omniwmctl query workspace-bar --format json
omniwmctl query workspaces --format json
omniwmctl query focused-window --format json
omniwmctl command move-column-to-workspace <workspace-id>
```

`workspace-bar` использовать как основной источник информации о приложениях.

`workspaces` использовать для получения полного списка доступных воркспейсов, их реальных ID, названий и порядка.

`focused-window` использовать для определения исходного окна до открытия chooser.

Допускается использование дополнительных команд OmniWM для надёжного восстановления фокуса.

### Обязательная проверка совместимости

До реализации основного функционала необходимо проверить доступные команды и структуру ответов именно OmniWM 0.7.6.

Выполнить:

```bash
omniwmctl version
omniwmctl query workspace-bar --format json
omniwmctl query workspaces --format json
omniwmctl query focused-window --format json
omniwmctl query commands --format json
```

Проверить, что `move-column-to-workspace` и механизм фокусировки исходного окна доступны в установленной версии.

Не предполагать, что текущая онлайн-документация точно соответствует 0.7.6.

Реализовать отдельный слой нормализации JSON, не смешивая parsing CLI-ответов с кодом UI.

Учитывать, что JSON CLI может содержать envelope с полями `ok`, `result`, `kind`, `payload`.

Не использовать отображаемое имя workspace в качестве внутреннего идентификатора, поскольку названия могут повторяться.

При отсутствии нужных данных в `workspace-bar` допускается fallback через `query windows`, если поддерживается установленной версией.

## 6. Перенос колонок и управление фокусом

Это критически важная часть реализации.

При открытии `hs.chooser` фокус macOS может переходить на Hammerspoon, поэтому нельзя предполагать, что после закрытия chooser OmniWM автоматически сохранил правильную исходную колонку.

Требования:

1. До открытия меню зафиксировать исходное сфокусированное окно.
2. Сохранить его идентификатор OmniWM, если он доступен.
3. После выбора destination закрыть меню.
4. Корректно восстановить фокус исходного окна.
5. Убедиться, что операция переноса относится к исходной колонке.
6. Выполнить `move-column-to-workspace` с реальным ID destination.

Предпочтительно использовать управляемую последовательность асинхронных команд, а не фиксированные задержки `sleep`.

Если исходное окно уже закрыто или восстановить его фокус не удалось, не перемещать другую случайно сфокусированную колонку.

В таком случае завершить операцию с диагностическим сообщением.

**Обязательно переносить всю колонку**, включая содержащиеся в ней окна, а не только одно сфокусированное окно.

Работа с floating-окнами: если нет соответствующей Niri-колонки, корректно отменить операцию.

Перемещение на текущий workspace не должно вызывать нежелательных побочных эффектов.

## 7. Производительность

Главная цель — максимально быстрое появление готового меню после шортката.

### Архитектура кеширования

Использовать три отдельных кеша:

**Workspace cache**

- ID и названия воркспейсов.
- Принадлежность мониторам.
- Порядок отображения.
- Список приложений по workspace.

**Application icon cache**

- Ключ: `bundleId`.
- Значение: готовый `hs.image`.
- Повторно не загружать уже известные иконки.

**Composite icon cache**

- Ключ: состав списка приложений и параметры изображения.
- Значение: готовая составная `hs.image`.
- Перестраивать только при изменении набора иконок или конфигурации.

Ограничить размер кеша и очищать устаревшие записи по необходимости.

### Открытие меню

Запрещено блокировать основной поток Hammerspoon выполнением CLI-команд.

Использовать `hs.task`, а не синхронный `hs.execute` на критическом пути.

Если кеш уже заполнен:

1. Сразу показывать меню с кешированными данными.
2. Асинхронно проверять актуальное состояние.
3. Обновлять список, если он изменился.

Если кеш пуст, запросить актуальные данные и отобразить меню сразу после их получения либо показать безопасное состояние загрузки.

Не терять исходный фокус при фоновом обновлении данных.

При обновлении открытого меню сохранять пользовательский запрос и выделенную строку, насколько это позволяет `hs.chooser`.

### Обновление состояния

Для MVP использовать асинхронное обновление при открытии и при необходимости после переноса.

При желании добавить event-driven обновление через:

```bash
omniwmctl subscribe workspace-bar --reconnect --format ndjson
```

Подписка необязательна и не должна усложнять базовый вариант. Использовать её только при корректной обработке потока, переподключении и отсутствии утечек ресурсов.

Избегать агрессивного постоянного polling.

### Целевые показатели

- Повторное открытие из кеша: стремиться к задержке менее 100 мс.
- Меню не должно зависать при запросах CLI.
- Не должно быть заметной нагрузки CPU, когда меню закрыто.
- Иконки не должны пересоздаваться при каждом открытии.

Это целевые показатели, а не гарантированные характеристики. Измерить реальные задержки на целевой машине.

## 8. Конфигурация

Сделать конфигурационный Lua-объект.

Пример параметров:

```lua
local config = {
    hotkey = {
        modifiers = {"ctrl", "alt", "shift", "cmd"},
        key = "W",
    },

    maxIcons = 5,
    iconSize = 22,

    theme = "dark",

    showEmptyWorkspaces = true,
    showCurrentWorkspace = true,
    searchAppNames = true,

    refreshOnOpen = true,
    debug = false,

    cliPath = nil,
}
```

`cliPath = nil` означает автоматическое определение пути к `omniwmctl` при инициализации; предусмотреть явное указание полного пути.

Комбинация модификаторов соответствует Hyper на уровне стандартного `hs.hotkey`. Если требуется различать именно правые модификаторы, это отдельная настройка, которую не нужно реализовывать в MVP.

Не допускать дублирования хоткеев при повторной загрузке конфигурации Hammerspoon.

## 10. Обработка ошибок

Обработать следующие случаи:

- OmniWM не запущен.
- `omniwmctl` не найден.
- IPC выключен или недоступен.
- JSON содержит ошибку или неожиданную структуру.
- Нет доступных воркспейсов.
- Исходное окно закрыто.
- Исходное окно не относится к Niri-колонке.
- Workspace удалён до выполнения переноса.
- Приложение не имеет `bundleId`.
- Иконку приложения невозможно получить.
- CLI возвращает ненулевой exit code.
- Асинхронный запрос вернулся после закрытия меню.
- Пользователь быстро несколько раз нажал шорткат.

Ошибки не должны приводить к сбою Hammerspoon или перемещению неправильной колонки.

Логировать детали через `hs.logger`.

Не выводить большое количество диагностических сообщений в обычном режиме.

CLI запускать с массивом аргументов через `hs.task`, без небезопасной конкатенации shell-команд.

## 11. Тестирование и критерии приёмки

Проверить следующие сценарии:

- [ ] Меню открывается назначенным шорткатом.
- [ ] В меню присутствуют все доступные воркспейсы.
- [ ] Названия и номера соответствуют OmniWM.
- [ ] Иконки приложений соответствуют содержимому workspace.
- [ ] Пустые воркспейсы отображаются.
- [ ] Поиск и управление стрелками работают.
- [ ] `Enter` переносит всю колонку.
- [ ] `Escape` отменяет перенос.
- [ ] Перенос работает с колонкой из нескольких окон.
- [ ] Работает перенос между воркспейсами разных мониторов, если это поддерживает OmniWM.
- [ ] Не происходит случайного переноса чужой колонки из-за смены фокуса.
- [ ] Работают воркспейсы с номерами больше 9.
- [ ] Повторное открытие не пересоздаёт все иконки.
- [ ] Состояние обновляется после открытия/закрытия приложений.
- [ ] Нет утечек ресурсов при многократном открытии и закрытии.
- [ ] Перезапуск или недоступность OmniWM обрабатываются корректно.
- [ ] Повторная загрузка Hammerspoon не создаёт дублирующие hotkey.

Дополнительно измерить:

1. Cold start — первое открытие после запуска Hammerspoon.
2. Warm start — повторное открытие с заполненным кешем.
3. Время обновления данных о воркспейсах.
4. Время от выбора destination до завершения команды переноса.
